# 打包流程

从源码到可发布产物，一条龙跑完。

```
tools/
├── editor/      游戏库编辑器源码（Windows 桌面版，打成单文件 exe）
├── build/       打包脚本 + 本机路径配置
├── install/     一键安装脚本 + 面向用户的安装说明
└── docs/        本文档
```

---

## 0. 环境准备

| 需要什么 | 说明 |
|---|---|
| JDK 17 | `javac` / `jar` / `d8` / `apksigner` 都用它，路径写在 `config.json` 的 `jdk` |
| Android 构建工具 | `aapt2.exe`、`zipalign.exe`、`apksigner.jar`、`d8.jar`、`android.jar`（API 21+），放到 `_build/tc/` |
| Python 3.8+ | 打包脚本只依赖标准库；编辑器 exe 另需 `pyinstaller` + `pillow` |
| 原生内核包 | 每个 ABI 一个含 `lib/<abi>/*.so` 的 apk，放到 `_build/base-arm32.apk`、`_build/base-arm64.apk` |

`config.json` 里所有路径都相对仓库根目录（绝对路径也行）。

> 密钥密码不写进配置文件。打包前先设环境变量：
> ```powershell
> $env:ARCADE_KS_PASS = "你的keystore密码"
> ```

## 1. 准备游戏目录（sdcard 结构）

App 运行时从 `/sdcard/ChildhoodArcade/` 读游戏，目录长这样：

```
/sdcard/ChildhoodArcade/
├── nes/      games.json  covers/  roms/
├── arcade/   games.json  covers/  roms/   ← 另有 neogeo.zip / pgm.zip 等 BIOS
├── gba/      games.json  covers/  roms/
├── md/       games.json  covers/  roms/
└── sfc/      games.json  covers/  roms/
```

每个平台的 `games.json` 是格式化过的 JSON 数组，一行一个游戏：

```json
[
  {
    "id": "contra",
    "title": "魂斗罗",
    "path": "roms/contra.nes",
    "art": "covers/contra.png",
    "hash": "0834713e18a72b1941ceaf42d55043f12de7c8a82e35f21f2badfa59e294ecd3",
    "bytes": 131088,
    "aliases": "HDL,CONTRA,超级马里奥"
  }
]
```

`path` / `art` 是**平台内相对路径**。App 会自动补上平台前缀。

### 两条硬规矩

1. **封面必须是真正的 PNG。**
   有不少资源是「JPEG 内容却叫 `.png`」，Windows 编辑器用 Tk 预览，Tk 不认 JPEG 会显示空白。
   编辑器工具栏的「**封面体检**」按钮可以一键扫出来并就地转换（自动备份到 `covers_backup/`）。
   Android 端靠嗅探文件头能显示，但换别的工具就可能出问题，所以统一成 PNG 最省事。

2. **BIOS 别漏。**
   街机平台缺 `neogeo.zip` / `pgm.zip` 会报「当前游戏未能完成初始化」。

## 2. 合并目录表

APK 内置一份兜底目录 `assets/catalog.js`（`window.GAME_CATALOG=[...]`），
需要把 5 个平台的 `games.json` 合并进去，路径补上前缀：

```python
merged = []
for plat in ['nes', 'arcade', 'gba', 'md', 'sfc']:
    for g in json.load(open(f'{plat}/games.json', encoding='utf-8')):
        g['path'] = plat + '/' + g['path']
        g['art']  = plat + '/' + g['art']
        merged.append(g)
open('_build/catalog.merged.js', 'w', encoding='utf-8').write(
    'window.GAME_CATALOG=' + json.dumps(merged, ensure_ascii=False) + ';\n')
```

产物：`_build/catalog.merged.js`、`_build/deployment-resources.json`。

## 3. 打包

一条命令跑完四步：

```powershell
python tools/build/build_all.py
```

也可以单步执行：

| 脚本 | 干什么 | 产物 |
|---|---|---|
| `build_apk.py` | aapt2 编译资源 → javac+d8 编 dex → 塞原生内核 → zipalign → apksigner | `_out/童年游戏厅-v2.0-整合版-{通用,arm32,arm64}.apk` |
| `pack_games.py` | 把 sdcard 目录打成 `游戏数据包-v2.0.zip` | `_out/游戏数据包-v2.0.zip` |
| `build_editor.py` | PyInstaller 打编辑器单文件 exe | `_out/童年游戏厅游戏库编辑器.exe` |
| `build_release.py` | 整理发布目录 + 生成 `SHA256SUMS.txt` | `_out/release/` |

### 三个 APK 变体

| 变体 | 内容 | 大小 | 给谁 |
|---|---|---|---|
| `universal` | armeabi-v7a + arm64-v8a | ~157 MB | 绝大多数设备 |
| `arm32` | 只有 armeabi-v7a | ~88 MB | 老电视盒子 |
| `arm64` | 只有 arm64-v8a | ~94 MB | 新设备，体积最小 |

打包时会跳过 `libarcade.so`（用不到的 fba2012 内核）。

### 数据包分卷

GitHub Release 单个附件上限 **2 GiB**，数据包 3.9 GB 超了，得切：

```powershell
python tools/build/pack_games.py --split 1900
```

切完会同时生成 `合并数据包.py`，用户下齐 `.partN` 后跑一下就能合并。

## 4. 验证

### 设备端自检

App 有个 content provider 专门给脚本用：

```bash
adb shell content call --uri content://org.childhood.arcade.deployment --method health
adb shell content call --uri content://org.childhood.arcade.deployment --method diag --arg contra
```

`diag` 会真去加载那个游戏，返回 `{"ok":true,"engine":"fbneo-native-..."}`。
全量跑一遍能把「装得上但跑不起来」的揪出来。

> OPPO/ColorOS 的坑：`content call` 报 `Could not find provider` 时，
> 先 `am force-stop` 再 `am start` 让 App 起来，provider 才会注册上。

### 编辑器自检

编辑器支持无头自检，不用开窗口：

```bash
童年游戏厅游戏库编辑器.exe --selftest <游戏目录>
```

输出会告诉你 Pillow 有没有打进去、多少张封面能正常预览。

## 5. 常见问题

| 现象 | 原因 |
|---|---|
| `editor.exe` 一闪而过 | `import sys` 之类被删了 —— 静态检查一下再用 `python 游戏库编辑器.py` 跑一遍 |
| 封面预览空白 | 封面不是真 PNG，跑「封面体检」 |
| 街机报「未能完成初始化」 | 缺 BIOS |
| 打包报 `64位模拟核心校验失败` | `NativeCoreIdentity` 里记的 sha 前缀和 APK 里的 `.so` 对不上，换内核后要同步 |
| `adb install` 卡住 | 手机锁屏时 OPPO 会卡住，先解锁 |
